# Image Intake Router v3.1：实用字段与紧凑确认预览设计

日期：2026-08-07

状态：用户已确认，可进入实施计划

目标版本：`3.1.0`
目标 Schema：`image-intake-router.v3.1`

## 1. 背景

v3.0.0 已能执行真实视觉识别、统一事实整理、三段式确认预览和一次性 OpenClaw 交接，但真实订单测试暴露了四类体验问题：

1. 图片中可见的生产日期可能已进入事实层，却没有稳定出现在入库内容中。
2. 退款、短重退款、原价、优惠、会员权益和赠品推测占据大量确认页空间，但并不是用户希望记录的业务内容。
3. 商品全名混有品牌、营养宣传、工艺和营销词，导致预览与下游记录过长。
4. 入账与入库重复展示相同的九条商品明细，确认页臃肿且难以快速核对。

本次迭代只修改 `image-intake-router`。不修改随手账、食序管家或其他下游项目、接口、端口和数据库。

## 2. 设计目标

- 只记录真实支付结果：订单实付和商品行实付。
- 生产日期在图片明确可见时进入库存事实、入库内容和确认预览。
- 商品名称面向用户和下游使用简洁、稳定的核心名称。
- 商品明细默认只展示一次，避免入账与入库重复列出。
- 退款只用于内部判断商品是否有效，不显示、不记账、不交接退款金额。
- 保持现有真实视觉、最多一次定向补识别、一次确认和 OpenClaw 所有权边界。

## 3. 非目标

- 不处理退款入账、退款收入、余额变化或净额计算。
- 不记录原价、划线价、单价、活动优惠、优惠券、会员权益、配送费或包装费明细。
- 不推断零元商品是赠品、会员权益或促销。
- 不计算生产日期、到期日或保质期；只记录图片明确可见的生产日期。
- 不为下游 Skill 设计私有参数、单位枚举、重试或状态查询协议。

订单最终实付可以自然包含页面已计入的费用或优惠，但路由器不拆解、不解释，也不尝试用商品行金额反推优惠结构。

## 4. 数据分层

### 4.1 可见原文层

视觉识别仍可读到页面上的全部文字，以便正确区分最终实付、商品行实付、取消状态、全额退款状态和其他界面内容。原始图片、完整 OCR、路径和敏感信息继续不持久化。

### 4.2 统一事实层

统一事实只保留本产品需要的业务字段。

订单级保留：

- 商家；
- 真实交易时间；
- 订单状态；
- 最终实付金额；
- 页面声明、已识别和隐藏商品种类数；
- 商品内容是否完整。

商品级保留：

- 图片可见全名 `full_name`，仅用于证据、核对和去重；
- 简化展示名 `display_name`；
- 规格、购买数量和数量单位；
- 标称或实际重量/容量；
- 商品行实付金额；
- 生产日期；
- 商品有效性状态、食品类型和可见性状态。

不进入统一事实：

- 退款总额、商品退款金额和短重退款金额；
- 商品原价、划线价和展示单价；
- 活动优惠、优惠券、会员权益和节省金额；
- 包装费、配送费的拆分；
- “赠品”“免费”“会员专享”等推测标签。

### 4.3 退款的内部判断边界

采用用户确认的方案 A：

- 视觉阶段可以读取退款或取消文字，但只用于判断商品是否完成购买、是否收到以及能否入库。
- 全额退款、已取消或未收到的商品不进入可执行入账/入库内容。
- 短重或部分退款不自动否定已经收到的商品；商品仍可入库，但退款金额和短重说明不输出。
- 退款金额不写入统一事实、确认预览或 OpenClaw handoff。
- 对用户只给出业务结果，例如“该商品未计入”，不展示退款金额或退款计算过程。

## 5. 商品名称简化

### 5.1 两种名称各司其职

- `full_name`：保留图片可见原名，只用于证据、重叠截图去重和歧义检查。
- `display_name`：用于确认预览、入账内容、入库内容和 OpenClaw handoff。

简化名称不得参与重叠截图去重，避免两个不同商品因为都被简化成“鲜牛奶”而被错误合并。去重继续使用全名、规格、数量、状态和相邻上下文。

### 5.2 简化顺序

1. 移除零售平台、店铺和品牌前缀，例如“小象”。
2. 移除工艺与营销词，例如 `HPP`、冷榨、锁鲜、原生、高钙、进口、香甜。
3. 移除营养宣传和数值，例如 `3.6g 乳蛋白`、`5.0 蛋白质`。
4. 保留核心食品类别，例如鲜牛奶、豆浆、西兰花、香蕉、果蔬汁。
5. 只有在省略后会改变商品身份或影响用户区分时，才保留必要口味或类型，例如无糖豆浆、燕麦奶。
6. 规格、容量、包装数和数量不塞进名称，继续放在独立字段中。

示例：

| 可见全名 | 展示名 |
| --- | --- |
| 小象HPP奇亚籽牛油果青瓜液体冷榨复合果蔬汁 | 果蔬汁 |
| 原生高钙小象3.6g乳蛋白鲜牛奶 | 鲜牛奶 |
| 小象3.4g蛋白鲜牛奶 | 鲜牛奶 |
| 低德吟小象5.0蛋白质浓豆浆 | 豆浆 |
| 高原夏菜西兰花 | 西兰花 |
| 控温锁鲜云南生菜 | 生菜 |
| 佳农进口香甜蕉 | 香蕉 |

两个商品可以使用相同展示名；规格和各自的 `product_index` 负责区分，不能因此合并商品行。

## 6. 生产日期

- `production_date` 是库存内容的正式字段，不再只是可选的内部事实。
- 图片明确展示生产日期时，必须记录原文、规范化日期、证据和置信度。
- 初次视觉结果漏掉图片中清晰可见的生产日期时，构成 `visible-field omission`，可以触发唯一一次定向补识别。
- 必须区分生产日期、包装日期、到期日、最佳食用期和保质期；不得把其他日期冒充生产日期。
- 图片没有生产日期时，不估算、不警告、不输出“未显示”。
- 图片明确存在生产日期标签但内容不可读时，只在 `【需确认】` 中写一句，例如“鲜牛奶生产日期看不清”。
- 确认可见生产日期时，handoff 将其交给 OpenClaw；下游 Skill 是否使用由 OpenClaw 和下游自身规则决定。

## 7. 金额规则

- 订单层只记录唯一、明确标注的最终实付金额。
- 商品行只记录与该商品直接对应的行实付金额。
- 零元商品保留真实行实付 `¥0.00`，不解释为免费、赠品或会员权益。
- 不展示或交接原价、划线价、展示单价、优惠、退款和费用拆分。
- 不用退款抵扣订单实付，也不用商品行合计倒推页面优惠。
- 如果最终实付或商品行实付不能可靠确定，将该金额标为未知并列入 `【需确认】`，不得选择看起来最合理的数字。

## 8. 紧凑确认预览

默认采用“商品明细只展示一次”的方案。

```text
识别完成

【入账】
小象超市｜实付 ¥65.48

1. 甜玉米 约850g×2　¥11.78
2. 鲜牛奶 1.5L×1　¥10.90
3. 黄瓜 约700g×1　¥4.99
4. 西兰花 约600g×1　¥3.95
5. 豆浆 1L×2　¥13.00
6. 生菜 约500g×1　¥4.96
7. 香蕉 约800g×1　¥11.90
8. 鲜牛奶 260ml×3×1　¥3.00
9. 果蔬汁 300ml×1　¥0.00

【入库】
以上 9 种食品均入库。

生产日期：
鲜牛奶 1.5L｜2026-08-03
鲜牛奶 260ml×3｜2026-08-02
果蔬汁 300ml｜2026-08-01

【需确认】
交易时间未显示。

回复“确认”执行；也可回复“只记账”或“只入库”。
```

示例日期只演示排版，不代表测试订单中的真实日期。

### 8.1 入库段压缩规则

- 如果入账商品全部是可入库食品，写“以上 N 种食品均入库”，不重复九条明细。
- 如果只有部分商品可入库，列出可入库商品的简化名称和必要规格。
- 生产日期只列出已可靠识别日期的商品；没有任何生产日期时，整段省略。
- 同名商品必须带规格区分，例如“鲜牛奶 1.5L”和“鲜牛奶 260ml×3”。

### 8.2 `【需确认】` 只放可行动问题

允许出现：

- 真实交易时间缺失；
- 存在隐藏商品；
- 商品名称、数量、规格、实际支付或生产日期不可读；
- 某商品未计入且需要用户决定。

禁止出现：

- 优惠金额验算和倒推过程；
- 退款、短重退款和退款合计；
- 会员节省、赠品或专享价推测；
- 原价、划线价、单价和费用拆分；
- “页面已展开”“有收起按钮”等无须用户行动的界面描述；
- Schema 字段、preview ID、pass count、内部状态和工具名。

## 9. 确认与 handoff

- 图片回合仍然只展示预览，产生零次 handoff。
- 后续“确认”“可以”“没问题”“执行”“就这样”选择全部可执行内容。
- “只记账”只选择 accounting；“只入库”只选择 inventory。
- handoff 使用 `display_name`、真实实付、规格数量和可见生产日期。
- handoff 不含退款金额、原价、单价、优惠、会员权益、赠品推测和费用拆分。
- 重复确认仍返回已有交接状态，不产生第二次 handoff。
- OpenClaw 继续独占下游 Skill 的发现与调用；路由器不执行下游工具。

## 10. 状态与失败处理

- 没有视觉能力或初始识别失败时继续 fail closed，不生成可执行预览。
- 某一生产日期不可读不阻塞其他可靠商品；只提示对应商品。
- 隐藏商品不猜测，不触发扩大扫描；可靠可见商品仍可确认。
- 简化名称存在歧义时，以规格和商品行位置区分；无法安全简化时退回较短但仍可核验的原名。
- 退款或取消状态无法判断时，不凭金额猜测商品是否有效，列为待确认。

## 11. Schema 与兼容性

- 产品版本升级到 `3.1.0`，Schema 标识升级到 `image-intake-router.v3.1`。
- `display_name` 成为商品事实和两个业务内容视图的正式字段。
- `production_date` 在库存项目中继续是必需属性，值可为 `null`；非空时必须来自可靠事实。
- accounting 和 inventory 内容删除退款、原价、单价、优惠和费用拆分字段。
- 运行时测试必须证明两个视图都映射到同一商品事实，且默认输出不泄漏被排除字段。
- v3.1 不迁移、不修改任何下游数据。OpenClaw 和下游 Skill 只接收用户确认后的精简业务内容。
- v3.0.0 标签、Release 和回滚资产继续保留。

## 12. 验收标准

1. 示例九商品预览中不出现退款、短重、原价、单价、优惠、会员、免费或赠品解释。
2. 九个商品名称分别简化为甜玉米、鲜牛奶、黄瓜、西兰花、豆浆、生菜、香蕉、鲜牛奶、果蔬汁，并保留规格区分两种鲜牛奶。
3. 入账只展示订单最终实付和每行真实实付。
4. 零元果蔬汁展示 `¥0.00`，没有赠品推测。
5. 入库不重复全部商品明细；全部可入库时使用“以上 N 种食品均入库”。
6. 图片可见生产日期进入事实、入库内容、确认预览和 handoff；日期不存在时不显示占位。
7. 全额退款、取消或未收到商品不进入可执行内容；部分退款不删除已收到商品，但退款信息不输出。
8. 预计送达时间不能冒充交易时间；交易时间缺失只提示一句。
9. 图片首轮零 handoff，后续确认只交接一次，重复确认零新增 handoff。
10. 所有现有视觉安全、附件覆盖、未知事实 fail-closed、发布包和回滚安全测试继续通过。

## 13. 测试重点

- 名称简化表的逐项 golden tests。
- 相同展示名、不同规格的两种鲜牛奶不得错误去重。
- 生产日期可见、缺失、不可读和被初次遗漏后的定向补识别测试。
- 部分退款商品保留、全额退款/取消/未收到商品排除测试，且输出中无退款金额。
- 原价、优惠、会员权益、包装配送费和赠品推测的输出禁用测试。
- 零元商品真实价格测试。
- 全部可入库与部分可入库两种紧凑预览测试。
- accounting/inventory 与统一事实的 product index、display name、规格、数量、金额和生产日期映射测试。
- 确认、范围确认、纠正和重复确认测试。
- v3.1 确定性发布包、独立安装和 v3.0.0 回滚测试。
